# Mirage v1.0 M0–M1 实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 实现 M0（协议冻结、Mac 捕获编码 CLI、模拟服务端）与 M1（Android 解码显示、adb reverse 全链路），交付「Mac 画面镜像到 Android 设备」的可运行版本，不做输入。

**Architecture:** Mac 端 ScreenCaptureKit 捕获主屏 → VideoToolbox 低延迟 H.264 编码 → 自定义长度前缀帧协议 → TCP；Android 端 TCP 收流 → MediaCodec 硬解 → SurfaceView 等比显示。协议核心两端各用纯函数实现并有共享测试向量；平台层保持薄。

**Tech Stack:** Swift 6 / SwiftPM / ScreenCaptureKit / VideoToolbox / Network.framework；Kotlin 2.2 / Jetpack Compose / MediaCodec / SurfaceView；Python 3（联调工具）。

**Spec:** `docs/superpowers/specs/2026-11-13-mirage-design.md`

## Global Constraints

- Mac：macOS 14+，仅 Apple Silicon（arm64）。
- Android：minSdk 26，compileSdk 36，targetSdk 36。
- 编码：H.264 High profile、无 B 帧、`RealTime=true`、低延迟码控、按需 IDR。
- 帧协议：`[u32 length][u8 type][payload]`，大端，`length = 1 + payload`，单帧上限 8 MiB。
- 默认端口 7777；M1 走 `adb reverse`，**不实现 TLS**（TLS 属 M4）。
- v1.0 不做输入；INPUT（type 4）只定义不实现。
- 分辨率：捕获配置使用 `CGDisplayMode.pixelWidth/Height`；客户端等比适配。
- 过程文档（`docs/` 下设计与计划）暂不提交；代码按任务提交。
- 每个任务结束必须真机/本机跑通该任务的验证命令，不通过不进入下一任务。

## 环境前置

- 已核实：Xcode 27.2 / Swift 6.4、Android SDK platforms 33–37、build-tools 36/37、JDK 17（`/Library/Java/JavaVirtualMachines/corretto-17.0.18`）、Gradle wrapper 8.13 已缓存。
- **Android 首次 Gradle 同步需要外网**下载 Kotlin/Compose 依赖，当前环境无外网。离线时先执行 Task 1–7（Mac 侧与协议），Task 8–12 在联网或有依赖缓存的环境中执行。
- 设备：Android 平板（性能基准）与手机各一台，开启 USB 调试。

## Review Focus

1. **连接早于推流就绪**：客户端在 Mac 捕获/编码器就绪前连上时，不得崩溃或挂起——服务端在捕获与编码器启动成功后才监听（Task 4/6 验证）。
2. **发送积压**：慢链路或客户端渲染慢时，队列不得超过 3 帧，非关键帧直接丢弃，等下一个关键帧恢复（Task 5 单测）。
3. **畸形/超大帧**：长度字段 > 8 MiB、包被截断、未知 type 时，必须忽略未知 type、对超大/截断帧断开连接而不崩溃（Task 1 单测）。
4. **断线重连**：客户端断开后服务端不得崩溃，能在同一端口接受下一次连接（Task 4/6 验证）。
5. **静止画面保活**：无视频帧超过 1 秒时发送 PING，避免客户端误判断线（Task 4 单测，注入时钟）。
