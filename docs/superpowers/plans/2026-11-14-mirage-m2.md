# Mirage M2 实施计划（虚拟屏扩展模式）

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans. Steps use checkbox (`- [ ]`) syntax.

**Goal:** 让 Mac 端创建一块真实虚拟显示器并推流它，Android 端不变，实现随航式副屏。

**Architecture:** 用 ObjC 桥接目标封装私有 `CGVirtualDisplay`（SwiftPM 不能在同一 target 混编），Swift 侧提供 `VirtualDisplay`；`HelperApp` 增加 `--mode extend`，成功后捕获虚拟屏，失败回退主屏镜像。

**Tech Stack:** Swift 6、ObjC/SwiftPM bridge target、CoreGraphics 私有 API、ScreenCaptureKit。

**Spec:** `docs/superpowers/specs/2026-11-13-mirage-design.md` §6.1、§12 M2。

## Global Constraints

- macOS 14+，仅 Apple Silicon；私有 API，失败必须回退镜像。
- 默认仍是镜像；`--mode extend` 才创建虚拟屏。
- 本里程碑不支持触控输入、不支持设备分辨率自动协商（后续跟进）。
- 虚拟屏必须在进程退出时销毁，避免 ghost 显示器。

## Review Focus

1. **虚拟屏无法 online**：创建后 2 秒内未出现在 `CGGetActiveDisplayList` → 回退镜像并记录原因，不挂起。
2. **退出残留**：helper 停止/异常退出后不得留下 ghost 虚拟显示器。
3. **捕获尺寸**：HiDPI 虚拟屏捕获必须用像素尺寸（点×2），否则降采样。
4. **权限**：仍需要屏幕录制权限；失败提示与镜像模式一致。
5. **端口/连接**：extend 模式不得改变 TCP 端行为。

## Task 2：HelperApp extend 模式与回退

**Files:**
- Modify: `mac/Sources/mirage-helper/HelperApp.swift`
- Modify: `mac/Sources/mirage-helper/main.swift`
- Modify: `README.md`

**Interfaces:**
- CLI：`--mode extend|mirror`（默认 mirror）、`--width <points>`、`--height <points>`（默认 1280×800）。
- `HelperApp` 新增 `mode`、`pointWidth`、`pointHeight`；`stop()` 销毁虚拟屏。
- extend 流程：创建 → 轮询 online（≤2s）→ 用该 displayID 捕获；任一步失败 → 打印 `extend_fallback=<reason>` 并切主屏。

- [ ] **Step 1: 接入 extend 分支**

在 `run()` 里：mirror 用当前 `CGMainDisplayID()`；extend 创建 `VirtualDisplay`，`captureSize` 用其像素尺寸（经 3840×2160 上限适配）。监听仍在捕获成功后启动。

- [ ] **Step 2: 回退与销毁**

失败日志一行；`stop()` 与 `deinit` 销毁虚拟屏。进程收到 SIGINT 时也应销毁（`signal(SIGINT)` 处理器调用 `exit` 前销毁或依赖系统回收，记录已知限制）。

- [ ] **Step 3: 构建与真实联调**

Run: `cd mac && swift build && ./.build/debug/mirage-helper --mode extend`
Expected：日志出现 `extend display=<id> pixel=2560x1600`；另一个终端 `--list-displays` 能看到该屏；客户端连接后收到画面。
