# Mirage M4 实施计划（Wi-Fi、UDP、TLS、配对）

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 把 Wi-Fi 路径从明文 TCP 阶段 1 升级为可日常使用的无线链路：TLS 控制通道、UDP 视频分片与 NACK、码率自适应、二维码配对，并在 UDP/mDNS 失败时可靠回退。

**Architecture:** 控制与握手走 TLS/TCP（HELLO、SESSION_CONFIG、UDP_CONFIG、FEEDBACK、PING、CTRL、BYE）；视频默认走 AES-GCM/ChaCha20 加密的 UDP 数据报，1200 字节分片、按帧重组、缺口 NACK、按 deadline 丢帧；客户端每 100ms 上报反馈，Mac 调节编码码率。UDP 不可用时自动回退 TCP 视频，mDNS 失败时用二维码/手动 IP。

**Tech Stack:** Swift 6 / Network.framework / CryptoKit / Security / CoreImage / `swift-certificates`；Kotlin / `SSLSocket` / `DatagramSocket` / `javax.crypto` / ZXing；Python 联调工具。

**Spec:** `docs/superpowers/specs/2026-11-13-mirage-design.md` §5.7、§8.3、§9、§11、§12 M4。

## Global Constraints

- TCP 控制通道使用 TLS 1.2+；Android 8/9 最高只到 TLS 1.2，不能强制 1.3。
- 证书固定为叶证书 DER 的 SHA-256；固定失败必须断开，不得降级明文。
- Android 26/27 没有 ChaCha20-Poly1305 `Cipher` 时用 AES-256-GCM；由 `UDP_CONFIG.cipher` 协商，验收后回填主设计。
- 二维码必须携带 Mac 证书指纹；mDNS 仅 best-effort，二维码/手动 IP 是主路径。
- UDP 视频负载 ≤1200 字节（不含 16 字节头）；加密封装后总长仍小于 1500，避免 IP 分片。
- 视频头 16 字节：`seq`、`frame_id`、`frag_idx`、`frag_count`、`flags`、`payload_len`。
- NACK 在检测到缺口约 1 RTT 后发送；每包最多重传一次；超过帧 deadline 丢整帧，不阻塞后续帧。
- 关键帧缺任一分片时整帧不可用；不要因普通丢包频繁请求 IDR。
- 反馈周期 100ms；码率调整带迟滞，禁止振荡。
- 传输模式默认 `AUTO`：USB accessory 优先，其次已保存的 Wi-Fi，最后 `127.0.0.1:7777`；手动选择 `USB/Wi-Fi/TCP` 时不做静默回退。
- USB 插入/拔出、App 回到前台时重新评估传输；切换防抖 500ms，不重启 APK。
- Fake USB 仅 `BuildConfig.DEBUG` 可用，生产构建不得走模拟传输。
- Wi-Fi 明文会话不启用 v1.1 输入；输入只在 TLS 配对后开放。
- 执行时不自动提交；每个任务验证通过、用户确认后再提交代码。

## Review Focus

1. **TLS 固定失败**：指纹不匹配、证书链异常、主机名不符时，必须拒绝连接；不能因为“能连上”就放行。
2. **UDP 乱序/重复/丢失**：同一帧的分片可乱序到达、重复到达；重组器不能内存增长、不能把旧帧当新帧。
3. **关键帧不完整**：缺分片的关键帧不能送解码器；按 deadline 丢弃并等待下一关键帧，避免花屏。
4. **NACK 风暴**：丢包率高时 NACK 不能放大拥塞；每帧每分片只请求一次，限速。
5. **UDP 回退**：防火墙/AP 隔离导致 UDP 不通时，必须在数秒内回退 TCP 视频，不能黑屏。
6. **mDNS 失败**：本地网络权限被拒、跨 VLAN、AP isolation 时，必须给出二维码/手动 IP 路径，不能只显示“发现失败”。
7. **码率振荡**：反馈延迟/丢包抖动时，码率不能高频上下跳；设置上下限和冷却时间。
8. **密钥/nonce 复用**：同一会话 key 下 nonce 不得重复；日志不得输出 key、指纹以外的敏感材料。
9. **运行时传输切换**：Mac 打开 USB 后，Android 不重启 APK 也应从 TCP/Wi-Fi 切到 USB；关闭 USB 后按 `AUTO` 回退，手动模式不得静默改道。
10. **切换抖动**：USB 枚举/授权期间不能反复断连重连；切换时旧 client、解码器和 Surface 必须干净释放。

**Interfaces:**

UDP 视频数据报（16 字节头 + 载荷）：

```
u32 seq            # 每个发送的数据报 +1
u32 frame_id
u16 frag_idx       # 0-based
u16 frag_count     # 本帧分片总数
u8  flags          # bit0 SOF, bit1 EOF, bit2 KEY, bit3 NACK, bit4 HELLO, bit5 parity
u8  reserved
u16 payload_len    # 0..1200
... payload
```

- `flags.bit3=1` 表示 NACK：`frame_id` 为缺失帧，`frag_idx` 为 bitmap 起始分片，`frag_count` 为 bitmap 字节数，`payload` 为 bitmap（bit i = 起始+i 缺失）。
- `flags.bit4=1` 表示 UDP HELLO：空载荷，用于让 Mac 学习客户端 UDP 源地址。
- `UdpVideoHeader` / `UdpDatagram`、`encodeUdpDatagram`、`decodeUdpDatagram`。
- 反馈（type 0x0D，客户端 → Mac，28 字节）：

```
u16 fps_x10
u16 decode_ms
u16 dropped_frames
u16 queue_depth
u16 rtt_ms
u16 loss_permille
u32 recv_bitrate_bps
u32 arrival_delay_ms
u64 ts_us
```

- `UDP_CONFIG`（type 0x0C，Mac → 客户端）：

```
u16 udp_port
u8  cipher          # 1 = AES-256-GCM, 2 = ChaCha20-Poly1305
u8  key[32]
u8  nonce_prefix[4]
u8  flags           # bit0 = UDP 视频启用
```

- `CTRL` 追加：`5 = udp_failed`（客户端 → Mac，回退 TCP 视频），`6 = udp_ready`（客户端 → Mac，UDP HELLO 已发）。
