# Mirage v1.0 M0 实施计划（协议、Mac 捕获编码、模拟服务端）

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 完成 M0：冻结帧协议与跨语言测试向量，实现 Mac 端 ScreenCaptureKit 捕获、VideoToolbox 低延迟 H.264 编码、TCP 服务端与发送背压，并提供模拟 Mac 服务端供 Android 开发。

**Architecture:** Mac 端 ScreenCaptureKit 捕获主屏 → VideoToolbox 低延迟 H.264 编码 → 自定义长度前缀帧协议 → TCP；Python 工具提供测试客户端和模拟 Mac 服务端。协议核心用纯函数实现并有共享测试向量，平台层保持薄。

**Tech Stack:** Swift 6 / SwiftPM / ScreenCaptureKit / VideoToolbox / Network.framework；Python 3（联调工具）；ffmpeg（测试码流）。

**Spec:** `docs/superpowers/specs/2026-11-13-mirage-design.md`

**后续:** Android 解码与 adb reverse 全链路见 [M1 实施计划](2026-11-13-mirage-m1.md)。

## Global Constraints

- Mac：macOS 14+，仅 Apple Silicon（arm64）。
- 编码：H.264 High profile、无 B 帧、`RealTime=true`、低延迟码控、按需 IDR。
- 帧协议：`[u32 length][u8 type][payload]`，大端，`length = 1 + payload`，单帧上限 8 MiB。
- 默认端口 7777；本阶段不做 TLS、不做输入；INPUT（type 4）只定义不实现。
- 分辨率：捕获配置使用 `CGDisplayMode.pixelWidth/Height`。
- 过程文档（`docs/` 下设计与计划）暂不提交；代码按任务提交。
- 每个任务结束必须本机跑通该任务的验证命令，不通过不进入下一任务。

## 环境前置

- 已核实：Xcode 27.2 / Swift 6.4；macOS 屏幕录制权限。
- 联调工具：Python 3、ffmpeg。
- 设备：M0 不需要 Android 设备；M1 再连接平板与手机。

## Review Focus

1. **连接早于推流就绪**：客户端在 Mac 捕获/编码器就绪前连上时，不得崩溃或挂起——服务端在捕获与编码器启动成功后才监听（Task 4/6 验证）。
2. **发送积压**：慢链路或客户端渲染慢时，队列不得超过 3 帧，非关键帧直接丢弃，等下一个关键帧恢复（Task 5 单测）。
3. **畸形/超大帧**：长度字段 > 8 MiB、包被截断、未知 type 时，必须忽略未知 type、对超大/截断帧断开连接而不崩溃（Task 1 单测）。
4. **断线重连**：客户端断开后服务端不得崩溃，能在同一端口接受下一次连接（Task 4/6 验证）。
5. **静止画面保活**：无视频帧超过 1 秒时发送 PING，避免客户端误判断线（Task 4 单测，注入时钟）。
