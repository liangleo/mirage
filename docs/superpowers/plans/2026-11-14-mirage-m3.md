# Mirage M3 实施与验收计划（AOA、菜单栏 App、权限）

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 完成 v1.0 有线首选路径：AOA 免调试 USB、Android 自动拉起、Mac 菜单栏 App、屏幕录制权限与登录启动，交付「插线即用」的扩展屏。

**Architecture:** 独立 `mirage-aoa` 桥接进程用 libusb 完成 AOA 协议和 bulk 读写，把字节流转发到 helper 的 `127.0.0.1:7777`；Android 通过 `USB_ACCESSORY_ATTACHED` 自动拉起并复用同一帧协议；菜单栏 App 管理 helper、桥接、权限和登录项。

**Tech Stack:** C/libusb（静态链接）、Swift 6/SwiftUI/AppKit/SMAppService、Kotlin USB Accessory API、ScreenCaptureKit、TCC。

**Spec:** `docs/superpowers/specs/2026-11-13-mirage-design.md` §6、§8.1、§11、§12 M3。

> **状态（2026-11-14）：** M3 代码已实现并在 vivo V2309A 真机跑通。本计划用于回填任务边界、回归验收和后续修改；步骤未勾选表示需要按当前构建重跑一次回归。

## Global Constraints

- macOS 14+，仅 Apple Silicon；屏幕录制权限授予 Mirage.app。
- helper 只监听 `127.0.0.1:7777`；AOA 桥接不直接推流，只转发字节流。
- libusb 静态链接；产物不依赖 Homebrew dylib。
- Android minSdk 26；activity `singleTask`，支持 `USB_ACCESSORY_ATTACHED` 自动拉起。
- 两端 bulk 读写块均为 16 KiB，不匹配会静默截断或死锁。
- 正常停止服务必须把手机从 accessory 模式复位回普通 USB（目标状态 `charging,adb`）。
- 单实例 App；重复启动直接退出，helper 发现端口占用时报错，不静默降级。
- 执行时不自动提交；每个任务验证通过、用户确认后再提交代码。

## Review Focus

1. **device-speaks-first**：`START` 后设备可能先发数据；host 必须先读再写，否则握手死锁。
2. **helper 重启**：自动分辨率触发 `execv` 后，桥接必须重连并重放 HELLO；已连接的 Android 不能卡死。
3. **停止复位**：停止服务/退出 App 后手机不能卡在 accessory；不支持 reset 的 ROM 要提示拔插。
4. **热插拔**：拔出再插入后桥接自动重启；首次授权弹窗勾选“一律打开”后无需手动操作。
5. **TCC 稳定性**：稳定签名后重新编译不重复弹屏幕录制授权；ad-hoc 签名要明确提示重新授权。
6. **端口占用**：已有 helper 在跑时，新 helper 必须报错退出，不能变成镜像或抢占虚拟屏。

## Task 1：AOA 桥接与静态链接

**Files:**
- Modify: `tools/aoa_bridge.c`
- Modify: `tools/build_app.sh`
- Modify: `Makefile`
- Verify: `build/aoa_bridge`、`build/.Mirage.app/Contents/MacOS/mirage-aoa`

**Interfaces:**
- CLI：`mirage-aoa [--helper-host 127.0.0.1] [--helper-port 7777]`。
- 行为：`GET_PROTOCOL=51` → `SEND_STRING=52`（manufacturer/model/description/version/URI/serial）→ `START=53`；重枚举后重新打开设备；bulk 端点从描述符读取。
- SIGTERM：`libusb_reset_device`，退出码 0。
- 对 helper：TCP 连接、双向转发；helper 断开时保留 accessory 并重连。

- [ ] **Step 1: 构建静态产物**

Run:
```bash
make build.aoa
otool -L build/aoa_bridge
```
Expected: 构建成功；输出里没有 `libusb-1.0.dylib` 之类的动态依赖。

- [ ] **Step 2: 无设备时的行为**

Run:
```bash
./build/aoa_bridge
```
Expected: 找不到 Mirage accessory 时打印等待信息并退出/等待重试，不崩溃、不无限占用 CPU。

- [ ] **Step 3: 真机 AOA 联调**

前置：`brew install libusb` 已装；手机已装 APK；helper 在 `127.0.0.1:7777` 监听。

Run:
```bash
./build/aoa_bridge --helper-host 127.0.0.1 --helper-port 7777
```
Expected：
- 手机弹出 USB 授权；勾选“连接后一律打开 Mirage”后 App 自动拉起。
- 手机调试浮层显示 `USB`；`adb shell dumpsys usb` 可见 `0x18d1:0x2d00` 或 `0x2d01`。
- 画面正常，helper 日志出现 `client connected`。

- [ ] **Step 4: 停止复位**

Run: 在 App 主界面停止服务，或在桥接进程发 SIGTERM。
Expected: `adb shell dumpsys usb` 恢复普通模式（实测 `charging,adb`）；手机回到充电/调试状态。不支持的 ROM 记录型号和“需拔插”提示。

**Interfaces:**
- 桥接在 helper TCP 断开后指数退避重连（建议 0.5s → 1s → 2s，上限 5s）。
- 重连后重放最近一次 HELLO；helper 关闭旧连接，由桥接/客户端按现有 BYE 流程重同步。
- `MirageServer` 只允许一个客户端；新连接到来时关闭旧连接并重置解码器状态。

- BYE 后 `Session` 不再产生视频/输入动作。

Run: `cd mac && swift test --filter SessionTests`
Expected: PASS。

- [ ] **Step 2: 触发 helper 自动重启**

Run:
```bash
cd mac && swift run mirage-helper --mode extend --auto-size
```
用真机连接后旋转屏幕，触发 helper `execv` 重启。
Expected: 桥接日志出现重连；Android 端在断开后自动重连并恢复画面，无需拔插。
