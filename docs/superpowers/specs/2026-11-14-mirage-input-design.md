# Mirage M5 输入回传设计（v1.1）

版本：v0.1（草案，2026-11-14）
状态：方案已确认，待实现；按项目约定，过程文档不随实现进度提交，验收后统一同步。
依赖：[主设计文档](2026-11-13-mirage-design.md) 的协议、权限、安全与延迟约束。

---

## 1. 目标与范围

M5 阶段（版本号 v1.1）在 v1.0 显示链路上增加**输入回传**：Android 设备的触控、手势、键盘、手写笔事件发送给 Mac，由 Mac 注入为系统输入。

**目标**

1. 触控可直接操作 Mac 扩展屏上的窗口：点按、拖动、右键、滚动、缩放。
2. Android 软键盘可向 Mac 输入中英文；实体键盘可输入字符和常用快捷键。
3. 手写笔可绘制；压感、倾斜尽力而为。
4. 断开、暂停、切换分辨率/方向时，不留下按下的鼠标键或键盘键。
5. 输入只在已配对且用户授权的会话中生效；Wi-Fi 明文会话不启用输入。

**非目标**

- 完整的虚拟 HID / DriverKit 手写笔（v1.2 再评估）。
- 剪贴板同步、文件拖放、音频回传。
- 多指独立光标、触控板式相对定位（v1.1 只做绝对定位 + 手势）。
- Windows/Linux 主机、多客户端同时输入。
- 游戏级低延迟或反作弊兼容性承诺。

**已定交互默认值**

| 手势 | Mac 行为 |
|---|---|
| 单指轻点 | 左键单击 |
| 单指拖动 | 左键拖动 |
| 单指长按 | 右键单击 |
| 双指上下/左右滑动 | 滚轮滚动 |
| 双指捏合 | `Command + 滚轮`（缩放） |
| 双击 | 尽力识别为双击；不保证所有 App 生效 |
| 手写笔按下/移动/抬起 | 左键按下/移动/抬起，附带压力与倾斜 |

坐标采用**绝对定位**：点哪里，Mac 光标到哪里。默认开启本地触点提示（半透明圆点），补偿“手指已落下但画面还没回来”的反馈延迟。

## 2. 总体架构

```
Android InputView / IME / KeyEvent
        │  INPUT / KEY / TEXT / SCROLL
        ▼
MirageClient（现有 USB / TCP / Wi-Fi 字节流）
        │
        ▼
Mac MirageServer → Session 解析 → InputInjector → CGEvent
        │
        └─ 虚拟显示器坐标 / 权限 / 限速 / 释放所有按键
```

- 输入复用现有可靠字节流，不新开连接；视频与输入共用同一条 USB/TCP 连接。
- Android 只负责采集、归一化和手势判定；Mac 只负责坐标映射、注入和安全管理。
- 输入事件不进入录像/日志内容；日志只记录数量、丢弃数和延迟。

## 3. 协议扩展（proto v1，追加字段/消息）

### 3.1 能力协商

HELLO 的 `features` 追加位（客户端 → Mac）：

| bit | 含义 |
|---|---|
| 0 | 手写笔 |
| 1 | 压感 |
| 2 | 倾斜 |
| 3 | 悬停 |
| 4 | 触控/指针回传 |
| 5 | 键盘 |
| 6 | IME/文本 |
| 7 | 保留 |

SESSION_CONFIG 末尾追加 1 字节 `input_caps`（Mac → 客户端）：

| bit | 含义 |
|---|---|
| 0 | 指针/触控 |
| 1 | 键盘 |
| 2 | 文本/IME |
| 3 | 手写笔 |
| 4 | 压感 |
| 5 | 倾斜 |
| 6-7 | 保留 |

- 旧版 Android 解码器只读取前 11 字节，追加字节可安全忽略；旧版 Mac 不发该字节时，v1.1 Android 按 `0` 处理并隐藏输入入口。
- 未完成配对/授权的会话，Mac 发送 `input_caps = 0`，并在需要时用 CTRL 说明原因。
- 输入能力只表示“允许接收”，不代表当前一定开启；用户仍可在 Android/Mac 侧暂停。

### 3.2 INPUT（0x04，指针）

沿用主设计文档 §5.5 的 32 字节布局：

```
u16 count
count × 32 字节：
  u8  kind        # 1 down, 2 move, 3 up, 4 cancel, 5 hover
  u8  pointer_id
  u16 buttons     # bit0 主键, bit1 次键, bit2 笔侧键, bit3 橡皮擦
  f32 x, f32 y    # 0..1，相对画面内容区（已去掉黑边）
  f32 pressure    # 0..1
  f32 tilt_x, f32 tilt_y   # 角度
  u64 ts_us
```

补充约定：

- 一个 `MotionEvent` 及其历史点合并为一帧，单帧最多 32 个点；超出时丢弃最旧的历史点，保留最新状态。
- `ts_us` 取 `MotionEvent.eventTime * 1000`，仅用于延迟统计和排序，不要求两端时钟同步。
- `kind=4 cancel` 表示释放当前指针且不产生一次新的点击；用于拖动中第二根手指加入、旋转、暂停等场景。
- `pointer_id` 在同一次手势内稳定；手写笔固定为 0。
- 坐标越界由 Mac 端 clamp 到虚拟显示器范围内；Android 端也应先 clamp。

### 3.3 KEY（0x09，键盘按键）

```
u8  action        # 1 down, 2 up
u8  modifiers     # bit0 Shift, bit1 Control, bit2 Option, bit3 Command
                  # bit4 Caps Lock, bit5 Fn
u8  flags         # bit0 自动重复, bit1 来自 IME
u8  reserved
u16 keycode       # Android KeyEvent.keyCode；未知填 0
u32 unicode       # Unicode scalar，未知填 0
u64 ts_us
```

- 可打印的实体键盘字符同时带 `keycode` 和 `unicode`。Mac 的注入规则：
  - 带 Command/Control/Option 修饰键，或功能键/方向键/退格/回车等非打印键：按 `keycode` 映射为 macOS 虚拟键码。
  - 其余可打印字符：优先用 `unicode` 注入，尊重 Android 侧布局与输入法结果。
- 修饰键按下/抬起时，`modifiers` 包含该键自身状态；Mac 对应发送 `flagsChanged`，并给后续事件设置 flags。
- `flags.bit0` 为 true 时，Mac 给 key down 设置自动重复标记。
- 找不到映射且没有 `unicode` 的键直接丢弃，并计数；不关闭连接。

### 3.4 TEXT（0x0A，提交文本）

```
u16 byte_len      # UTF-8 字节数，1..4096
... UTF-8
u64 ts_us
```

- 只用于 IME 已提交的文本（`commitText`），以及需要按文本而非按键注入的场景。
- 超长文本拆成多帧；Mac 按 UTF-16 分段调用 `CGEventKeyboardSetUnicodeString`。
- 实体键盘的可打印字符不走 TEXT，避免与 KEY 重复输入。

### 3.5 SCROLL（0x0B，滚动/缩放）

```
u8  phase         # 1 begin, 2 change, 3 end
u8  flags         # bit0 Command（捏合缩放）, bit1 精确像素单位
u16 reserved
f32 dx, f32 dy    # 设备点；+x 向右，+y 向下（手指移动方向）
u64 ts_us
```

- 双指滑动发送滚动；捏合发送 `flags.bit0=1`，`dy` 由缩放比例换算，phase 标记开始/变化/结束。
- Mac 注入 `CGEvent(scrollWheelEvent2Source:...)`，默认遵循 macOS“自然滚动”方向；灵敏度在实现期标定，保留配置项。
- 滚动与缩放不产生指针按下，不和单击冲突。

### 3.6 CTRL 扩展

现有 `CTRL` 第 1 字节为 1 时表示请求关键帧。v1.1 追加：

| code | 方向 | 含义 |
|---|---|---|
| 2 | 客户端 → Mac | `release_all`：释放所有按下的鼠标键/键盘键，无 payload |
| 3 | Mac → 客户端 | `input_enabled`：输入可用；客户端可显示输入入口 |
| 4 | Mac → 客户端 | `input_disabled`：`u8 reason_len` + UTF-8 原因；客户端隐藏/禁用输入并提示 |

未知 code 忽略。Mac 在收到 BYE、连接关闭、输入暂停、helper 重启时也必须自行执行 `release_all`，不依赖客户端。

### 3.7 兼容性

- 新增消息类型 0x09–0x0B 只由 v1.1 客户端发送；旧 Mac 按现有规则忽略未知 type。
- 新字段一律追加在末尾；解码器不得因尾部多余字节报错。
- INPUT 的 32 字节布局不变；kind 1–5 语义不变。
- 每个里程碑把新消息加入 `protocol/vectors.json`，两端共享测试向量。

## 4. Android 端设计

### 4.1 输入开关与可操作区域

- 连接成功且 `input_caps` 含指针能力后，控制面板出现「输入」开关；默认开启，用户可随时关闭。
- 输入开启时：
  - 视频上方覆盖透明 `InputView`，捕获 `MotionEvent` 与 `KeyEvent`。
  - 右侧 24dp 宽的手柄区域不捕获，保证控制面板仍可滑出；同时在 API 29+ 调用 `setSystemGestureExclusionRects` 排除该区域，减少系统返回手势冲突。
  - 面板展开时暂停捕获，关闭面板后恢复。
- 输入关闭或 `input_caps=0` 时，不显示触点提示，所有触摸交还系统。
- 本地触点提示：在触点位置画半透明圆点/短暂涟漪，只在本机显示，不上传。

### 4.2 触控状态机

为避免“第一根手指落下先点了一下，第二根手指才加入滚动”，单指点击延迟到手势确定后再发送：

- **单指按下**：先不发送；累计位移超过触摸阈值（建议 6dp）后，发送 `down` + 历史 `move`，进入拖动。
- **单指抬起且未超过阈值**：发送 `down` + `up`，即单击。
- **长按**：按住超过 500ms 且未移动，发送右键 `down`，抬起时发送右键 `up`；不发送左键。
- **拖动中第二指加入**：先发 `cancel` 结束左键拖动，再进入双指滚动；不产生额外点击。
- **双指**：不发送指针，只发送 SCROLL；根据两指距离变化判断捏合。
- **三指及以上**：v1.1 忽略，发送 `cancel` 清理状态。
- **手写笔**：使用 `TOOL_TYPE_STYLUS`/`ERASER`，按下立即发送 `down`（不做点击延迟），移动带历史点，抬起发送 `up`；支持 hover 与侧键/橡皮擦位。

坐标归一化基于视频内容区（`VideoView` 实际绘制区域），不是整个屏幕；黑边区域的事件忽略或 clamp。旋转后重新计算内容区并清理未完成手势。

### 4.3 键盘

- **软键盘**：控制面板提供「键盘」按钮，显示一个不可见的 `EditText` 并唤起 IME。
  - 自定义 `InputConnection`：
    - `commitText` → 发送 TEXT；
    - `setComposingText` → 仅本地候选，不发送；提交后再发 TEXT；
    - `deleteSurroundingText(before, after)` → 发送对应次数的退格 KEY；
    - `sendKeyEvent` / 回车 / 方向键 → 发送 KEY；
    - 不接受本地文本插入，避免与 Mac 重复。
  - 窗口使用 `adjustNothing`，IME 覆盖在视频上方，不触发布局缩放导致分辨率/触摸映射变化。
- **实体键盘**：Activity/InputView 的 `dispatchKeyEvent` 捕获；可打印字符发送 KEY（带 unicode），导航/快捷键发送 KEY；不额外发送 TEXT。
- **修饰键**：Shift/Ctrl/Option/Command 的按下与抬起实时发送，保证 `Cmd+C`、`Cmd+Tab` 等组合可用。
- **输入法差异**：中文输入法只转发已提交文本；拼音候选阶段留在 Android 本机显示。日文/韩文等同样按 commit 处理。
- **焦点与生命周期**：隐藏键盘、输入关闭、Activity 暂停、旋转、断开连接时，发送 `release_all` 并清理按键状态。

### 4.4 发送与限速

- 指针移动合并到最多 120Hz 发送；点击、抬起、按键不合并。
- 输入队列有界（建议最多 2 帧/约 16ms 的量）；队列满时丢弃旧 move，不阻塞解码/渲染线程。
- 输入写入与现有 `MirageClient` 的视频/心跳写共用同步保护；写入失败按现有断线流程处理。
- 断线时优先发送 `CTRL release_all`，失败也直接关闭；Mac 侧同样有兜底释放。

## 5. Mac 端设计

### 5.1 InputInjector

新增独立注入层，Session 只解析事件，不直接调用 CGEvent，便于单元测试。

- **权限**：用 `AXIsProcessTrustedWithOptions` / `CGPreflightPostEventAccess` 检查，首次需要时弹系统授权引导；菜单栏显示「需要辅助功能权限」并提供打开系统设置的按钮。
- **坐标映射**：
  - 通过 `CGDisplayBounds(displayID)` 取虚拟显示器全局矩形（可能为负 origin，副屏在左侧时）。
  - `global = bounds.origin + (normalized * bounds.size)`，再 clamp 到该矩形。
  - 所有鼠标事件使用全局坐标；拖动到边缘时停在边缘，不跳到主屏。
- **鼠标**：
  - `mouseMoved` / `leftMouseDown` / `leftMouseUp` / `leftMouseDragged`；右键同理。
  - 双击：Mac 侧对同位置、短间隔的两次点击设置 `clickState=2`，作为尽力支持。
  - 滚动：`scrollWheelEvent2Source`，携带精确像素单位和自然滚动方向；捏合时附加 Command flag。
  - 手写笔：设置 `CGEvent` 的 tablet 字段（压力、倾斜、设备 ID、指针类型），不保证目标 App 使用；v1.2 再评估虚拟 HID。
- **键盘**：
  - 维护 Android keycode → macOS 虚拟键码映射表（字母、数字、标点、方向、功能键、退格、回车、Esc、Tab、Delete 等）。
  - 修饰键发送 `flagsChanged`；普通键发送 keyDown/keyUp；重复键设置自动重复字段。
  - 文本通过 `CGEventKeyboardSetUnicodeString` 分段注入；不经过剪贴板。
  - `IsSecureEventInputEnabled()` 为 true 时（密码框、登录窗口）拒绝键盘注入并提示，不静默失败。
- **释放所有**：
  - 记录当前按下的鼠标键和键盘键；收到 `release_all`、BYE、socket 关闭、输入暂停、helper 退出时全部释放。
  - 释放操作幂等，重复调用无副作用。
- **限速与校验**：
  - 输入事件上限 500 次/秒；超出丢弃并计数，不关闭连接。
  - 校验帧长度、坐标有限性（拒绝 NaN/Inf）、文本长度、keycode 范围；畸形输入丢弃并计数。
  - 日志只记录事件数、丢弃数、注入延迟，不记录按键内容。

### 5.2 Session / Server

- 新增 INPUT/KEY/TEXT/SCROLL 解析，产出统一的 `InputEvent`：
  - `.pointer(...)`、`.key(...)`、`.text(...)`、`.scroll(...)`、`.releaseAll`
- 只有同时满足以下条件才交给 `InputInjector`：
  1. 会话已配对；
  2. 该 `device_id` 已允许输入；
  3. 用户未暂停输入；
  4. 当前链路满足安全要求（AOA 已本地确认；Wi-Fi 必须 TLS 且已配对）。
- 不满足时丢弃输入；首次发送一次 `CTRL input_disabled` 说明原因，避免客户端反复提示。
- 输入事件与视频事件在同一连接上按到达顺序解析；不阻塞视频发送线程。

### 5.3 菜单栏 App

- 显示输入状态：已启用 / 已暂停 / 需要辅助功能权限 / 当前设备未授权。
- 「暂停输入」为紧急开关：立即 `release_all`，丢弃后续输入，直到用户恢复。
- 首次允许某设备输入时，在设备确认弹窗中加入「允许此设备控制 Mac」；按 `device_id` 持久化。撤销授权后，该设备只能看画面。
- 菜单栏在输入启用时显示明确标识，避免用户不知情。
- 权限归属：helper 由 Mirage.app 启动，通常继承 app 的辅助功能授权。I0 阶段用最小探针验证；若 TCC 不按 responsible process 归属，改为 helper 通过本机回环 IPC 把输入转给菜单栏 App 注入，协议不变。

## 6. 安全与隐私

- **输入必须经过配对/授权**：Wi-Fi 明文会话永不启用输入；AOA 首次连接需要 Mac 本地确认「允许控制」，不能仅凭 USB 插入就注入。
- **最小权限**：只使用辅助功能（注入）与已有的屏幕录制/本地网络权限；不申请输入监控（除非后续做全局快捷键监听）。
- **紧急停止**：菜单栏「暂停输入」和断开连接都能立即释放所有按键；Android 侧关闭输入同样发送 `release_all`。
- **范围限制**：触控坐标 clamp 在 Mirage 虚拟显示器内；键盘快捷键仍可影响全系统，这是用户已授权的输入能力，需在授权文案中写明。
- **不记录内容**：不记录按键字符、不记录屏幕内容；只记录事件计数和延迟。
- **安全输入**：macOS 安全输入模式下拒绝键盘注入并提示用户在本机输入；不尝试绕过。
- **速率与合法性**：限速、长度校验、坐标校验；异常输入丢弃，不因单帧畸形断开视频。
- **锁屏/休眠**：锁屏或会话失活时暂停注入并释放所有按键；恢复后需重新满足授权条件。

## 7. 延迟预算

| 段 | USB 目标 | Wi-Fi 目标 |
|---|---|---|
| Android 采集 + 组帧 | 1–3ms | 1–3ms |
| 传输到 Mac | 1–5ms | 10–30ms |
| Mac 解析 + CGEvent 注入 | 1–3ms | 1–3ms |
| 光标移动被捕获/编码/回显 | 10–25ms | 15–40ms |
| **输入事件到 Mac 注入 p95** | ≤10ms | ≤50ms |
| **触摸到画面反馈 p95** | ≤100ms | ≤180ms |

- 触摸的视觉反馈依赖整条显示链路，绝对触控没有本机光标可看；本地触点提示用于降低主观延迟。
- 调试浮层增加 `input` 延迟（Android 发送时间与 Mac 注入确认的估算值），每 60 帧汇总一次。
- 不以牺牲视频稳定性为代价优化输入；输入队列满时丢旧 move。

## 8. 里程碑与估算

| 阶段 | 内容 | 估算 |
|---|---|---|
| I0 | 协议扩展、测试向量、两端编解码与 Session 单测 | 0.5–1 天 |
| I1 | Android 触控采集 + Mac 指针注入 + 辅助功能引导 + 单击/拖动/右键/滚动 | 3–5 天 |
| I2 | 软键盘 IME + 实体键盘 + 修饰键/快捷键 + 中文输入 | 3–5 天 |
| I3 | 双指滚动/捏合、手写笔压力/倾斜、边缘手势与触点提示 | 3–5 天 |
| I4 | 授权/暂停/释放所有、限速、延迟统计、模拟器与真机验收 | 2–3 天 |

核心功能约 **2–3 周**；含多机型兼容、手写笔调参和真机验收约 **3–4 周**。先模拟器跑通，真机由用户统一确认。

## 9. 验收标准

1. 扩展屏上单指点击、拖动、长按右键、双指滚动、捏合缩放均生效，坐标无偏移（含黑边、旋转、副屏在左/右）。
2. 软键盘可输入英文、中文（提交后整段出现），退格、回车、方向键可用；实体键盘可输入字符和 `Cmd+C/V/Tab/Esc` 等常用快捷键。
3. 手写笔在绘图 App 中可画线；支持压感/倾斜的 App 尽力生效，不支持时不影响基本绘制。
4. 断开 USB/Wi-Fi、停止服务、暂停输入、旋转、切换分辨率后，无卡住的鼠标键或键盘键；重连后输入恢复正常。
5. 未授权设备、`input_caps=0`、Wi-Fi 明文会话无法注入；Mac 菜单栏有明确状态。
6. 输入事件到 Mac 注入 p95 达到 §7 目标；连续使用 2 小时无输入队列增长/内存增长。
7. 模拟器跑通全流程；真机（手机 + 平板）完成触控、键盘、手写笔和断连恢复验收。

## 10. 风险与待验证项

| 风险 | 影响 | 应对 |
|---|---|---|
| 辅助功能权限归属 helper | 注入被系统拒绝 | I0 探针验证 responsible process；失败则 helper → 菜单栏 App 回环 IPC 注入 |
| 安全输入模式 | 密码框无法输入 | 检测 `IsSecureEventInputEnabled`，明确提示，不绕过 |
| IME 重复/丢字 | 中文输入错乱 | 只转发 commitText；组合阶段本地处理；隐藏 EditText 不本地插入 |
| 边缘手势冲突 | 右滑面板/返回手势抢触摸 | 保留手柄安全区 + `systemGestureExclusionRects` + 输入模式提示 |
| 多点触控语义 | 误点击/滚动方向不一致 | 单击延迟到手势确定；滚动方向/灵敏度配置化并实测标定 |
| 手写笔保真度 | 专业绘图 App 不识别压力/倾斜 | CGEvent 尽力而为；v1.2 评估虚拟 HID |
| 键盘布局差异 | 特殊字符/快捷键错位 | 可打印字符优先 unicode；快捷键走 keycode；映射表单测 |
| 触摸反馈延迟 | 主观“跟手”差 | 本地触点提示；优化输入合并与注入路径 |
| TCC 授权被撤销 | 输入突然失效 | 运行时检测并提示；暂停输入并释放所有键 |
| 多显示器/负坐标 | 点击落到主屏 | 统一用 `CGDisplayBounds` 全局坐标并 clamp |
